# 告警中心

规则命中或物模型事件触发后产生告警事件，告警中心负责事件的集中呈现、确认与处置追溯。

![告警事件](/images/alarms.png)

## 态势统计

页面顶部三个指标：

| 指标 | 含义 |
| :--- | :--- |
| 待处理告警事件 | 状态为"未处理"的事件数，需重点关注 |
| 今日告警总数 | 当日产生的事件总量 |
| 告警响应恢复率 | 已恢复事件占比，反映现场异常的自愈与处置效率 |

## 查询事件

| 条件 | 说明 |
| :--- | :--- |
| 关键字 | 按告警编号、设备 ID、监控点或消息模糊搜索 |
| 告警级别 | CRITICAL 紧急 / HIGH 严重 / WARN 警告 / INFO 提示 |
| 处理状态 | 未处理（0）/ 已确认（1）/ 已恢复（2） |
| 关联规则 | 按触发规则过滤 |

## 事件列表

| 列 | 说明 |
| :--- | :--- |
| 事件 ID | 事件唯一编号 |
| 告警级别 | 四级色标显示 |
| 关联触发规则 | 触发该事件的规则 |
| 触发设备 / 点位 | 设备与点位信息 |
| 告警描述及实时数值快照 | 触发时刻的点位实时值（快照），确认异常幅度的直接依据 |
| 触发时间 | 事件发生时间 |
| 响应状态 | 未处理 / 已确认 / 已恢复 |

## 处置流程

1. **确认**：现场或远程核实异常后，将事件置为"已确认"，避免重复通知；
2. **处置**：在详情弹窗的**处置记录与说明**中填写告警原因、现场排查情况或处置结果，形成追溯流水；
3. **恢复**：点位回到正常范围后事件自动转为"已恢复"，也可人工置为恢复。

::: tip
处置说明是经验沉淀的关键。建议至少记录"原因 + 措施"两项，便于后续同类告警的快速定位。
:::

## 与其它模块的关系

- 告警由[规则引擎](./rules.md)的判定逻辑或物模型事件触发，调整判定阈值请回到规则配置；
- 事件中记录的实时触发值可与[数据监控](./data.md)的历史快照相互印证；
- 大盘的"待处理告警事件"与本页"未处理"数量一致，可作为值班的巡视指标。
